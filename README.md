# דשבורד מכירות – Zvikah

דשבורד מכירות אינטראקטיבי המבוסס על דו"ח "WorkflowsExport" שמיוצא מהמערכת (CRM). האפליקציה רצה כולה בדפדפן (client-side בלבד, ללא שרת/מסד נתונים) — הנתונים נשמרים מקומית בדפדפן שלך (`localStorage`) בין שימושים.

## מה יש בפנים

- **כרטיסי KPI**: סה"כ פרמיה צפויה, פרמיה צפויה לפי קצב החודש (הערכה לפי ימי עבודה שחלפו), מספר עסקאות, פרמיה ממוצעת, לקוחות ייחודיים, פילוח לפי סטטוס (הופק/בטיפול/בוטל) עם השוואה לחודש קודם.
- **הדוח מוגבל לשתי עסקאות המכירה האמיתיות** — שיחלוף מוצר ורכישת מוצר חדש. מינוי סוכן מוצג כשורה נפרדת (עסקאות + פרמיה) ואינו נכלל בסכומים הראשיים.
- **תרשימים**: מכירות חודשי כללי (עם בחירת טווח 6/12/24 חודשים), מכירות לפי נציג לחודש נבחר (כולל "קצב חודשי" לפי ימי עבודה), מכירות לפי חברות ביטוח, ופילוח שיחלוף/רכישה לפי סטטוס אמיתי — לכל תרשים יש גם תצוגת טבלה חלופית.
- **סינון**: "כל הזמנים" / בחירת חודש ספציפי / בחירת שנה / טווח מותאם אישית, נציג, סטטוס, סוג תהליך, יצרן, סוג מוצר, וחיפוש חופשי.
- **לקוחות שנסגרו לאחרונה**, **טבלת כל הלקוחות** (מרוכזת לפי לקוח) ו**טבלת כל העסקאות** — כולן עם מיון, עימוד וייצוא ל-CSV.
- **עדכון יומי**: כפתור "עדכון דו״ח יומי" מאפשר להעלות את קובץ ה-`xlsx` שמיוצא מהמערכת בכל יום — הוא מחליף את הנתונים הקיימים (כל העלאה נחשבת "תמונת מצב" מלאה ועדכנית).
- מצב כהה/בהיר, תמיכה מלאה ב-RTL, ועיצוב רספונסיבי.

## הרצה מקומית

דורש Node.js גרסה 20 ומעלה.

```bash
npm install
npm run dev
```

האפליקציה תיפתח בכתובת שמודפסת בטרמינל (בדרך כלל `http://localhost:5173`).

## בנייה לפרודקשן

```bash
npm run build
```

התוצר הבנוי (סטטי לחלוטין) ייכתב לתיקיית `dist/`. ניתן לארח אותו בכל שירות אחסון סטטי — אין צורך בשרת Node בזמן ריצה.

```bash
npm run preview   # בדיקה מקומית של תוצר הבנייה
```

## פריסה ל-Vercel

1. ב-[vercel.com](https://vercel.com) → **Add New → Project** → בוחרים את הריפו הזה.
2. Vercel מזהה אוטומטית שזה פרויקט Vite — אין צורך בהגדרות ידניות.
3. **לפני ה-Deploy הראשון**, מגדירים משתני סביבה להגנת סיסמה (ראו "אבטחה" למטה): `DASHBOARD_USER`, `DASHBOARD_PASSWORD`.
4. Deploy — תוך דקה מקבלים כתובת `*.vercel.app` שמתעדכנת אוטומטית בכל push לענף המחובר.

## אבטחה

⚠️ **הריפו הזה חייב להיות פרטי (Private) ב-GitHub**, כי הוא מכיל את קוד המערכת שמנהלת נתוני לקוחות. אם הריפו ציבורי: Settings → Danger Zone → Change visibility → Private.

הדשבורד מציג נתונים עסקיים/לקוחות רגישים, ולכן כשהוא פרוס באינטרנט (Vercel וכו') הוא מוגן בשתי שכבות:

1. **`middleware.ts`** בשורש הפרויקט — חוסם *כל* בקשה (כולל קובצי ה-JS/CSS עצמם) ברמת ה-Edge של Vercel עד להזנת שם משתמש וסיסמה (HTTP Basic Auth). זה לא רץ בהרצה מקומית (`npm run dev`) — רק בפריסה בפועל בענן. יש להגדיר בפרויקט ב-Vercel (Settings → Environment Variables):
   - `DASHBOARD_USER`
   - `DASHBOARD_PASSWORD`

   בלי שני המשתנים האלה, הגישה **נחסמת לגמרי** (ברירת מחדל בטוחה). זו הגנה בסיסית (סיסמה משותפת אחת) ולא מערכת התחברות מלאה — מספיקה למניעת גישה מקרית של מי שיש לו את הקישור, אבל לא תחליף לאימות משתמשים אמיתי אם תרצה בעתיד למכור/לשתף את המערכת עם מספר סוכנים.
2. **נתוני הדוגמה בקוד (`src/data/seedData.json`) הם מומצאים לחלוטין** — שמות לקוחות ונציגים אקראיים, לא מבוססים על אף לקוח אמיתי. כל שאר השדות (סטטוסים, סכומים, תאריכים, חברות ביטוח) משקפים את המבנה האמיתי של הדוח לצורך הדגמה. **הנתונים האמיתיים שלך** (שאתה מעלה דרך "עדכון דו״ח יומי") **נשארים תמיד רק בדפדפן שלך** ואינם נשלחים לשום שרת.

## איך מעדכנים את הנתונים

1. מייצאים מהמערכת את הדו"ח היומי (`WorkflowsExport`, קובץ `.xlsx`).
2. לוחצים על "עדכון דו״ח יומי" בפינה הימנית העליונה ובוחרים את הקובץ.
3. הדשבורד מנתח את הקובץ, מחליף את הנתונים הקיימים, ושומר אותם בדפדפן (במחשב/בדפדפן הנוכחי בלבד).

הפורמט הנדרש הוא זהה לדו"ח שמיוצא מהמערכת — העמודות מזוהות לפי שם הכותרת (בעברית), כך שגם אם סדר העמודות משתנה בין ייצוא לייצוא, הייבוא ימשיך לעבוד. עמודת חובה: **מספר תהליך**.

> שימו לב: מכיוון שהאפליקציה שומרת את הנתונים ב-`localStorage` של הדפדפן, הנתונים **לא** משותפים אוטומטית בין מכשירים/דפדפנים שונים. כל מכשיר שרוצים להציג בו את הדשבורד צריך לבצע העלאה של הדו"ח בעצמו.

ניתן לשחזר בכל רגע את נתוני הדוגמה (המומצאים) דרך כפתור פח האשפה בכותרת.

## מעקב קמפיין גוגל אדס (ניהול עצמי)

לשונית נוספת ("קמפיין גוגל אדס") למעקב אחרי קמפיין השיחות בגוגל אדס בעצמכם, בלי תלות בדיווח של גורם חיצוני:

- **ייבוא נתונים**: העלאת קובץ CSV שמיוצא מגוגל אדס (דוח ביצועים יומי), או הדבקה ישירה של טבלה מתוך ממשק גוגל אדס. הזיהוי לפי שם העמודה (תאריך/עלות/קליקים/שיחות) עובד גם בעברית וגם באנגלית.
- **מעקב תקציב**: כרטיסי KPI (הוצאה עד כה, תחזית לסוף החודש, מספר שיחות, עלות לשיחה) ותרשים הוצאה יומית מול קצב תקציב — כדי לתפוס חריגה מתקציב מוקדם, לא בסוף החודש.
- **מדריך מובנה**: לשונית עם הנחיות מפורטות להשתלטות על ניהול החשבון (הרשאות אדמין), מבנה קמפיין, מילות מפתח, מעקב המרות שיחה, ורגולציית פרסום ביטוח בישראל.
- כמו הדשבורד הראשי — כל הנתונים נשארים בדפדפן שלך בלבד (`localStorage`), ללא חיבור ל-Google Ads API וללא שרת.

## מבנה הפרויקט

```
middleware.ts            הגנת סיסמה ברמת ה-Edge לפריסה ב-Vercel (ראו "אבטחה")
src/
  config.ts              קבועי מיתוג (שם החברה) וסוגי התהליך שנחשבים "מכירה"
  types.ts                טיפוסי הנתונים המרכזיים (כולל נתוני קמפיין גוגל אדס)
  lib/                    פענוח Excel/CSV, אגרגציות (מכירות + קמפיין), פורמט, אחסון מקומי, ימי עבודה
  hooks/                  ניהול מצב הנתונים (מכירות + קמפיין), ערכת נושא, אנימציית מספרים
  components/             רכיבי ה-UI (כותרת, סינון, KPI, תרשימים, טבלאות)
  components/ads/         לשונית מעקב קמפיין גוגל אדס (KPI, תרשים, ייבוא נתונים, מדריך)
  data/seedData.json      נתוני דוגמה מומצאים למכירות (לא נתוני לקוח אמיתיים)
  data/adsSeedData.json   נתוני דוגמה מומצאים לקמפיין גוגל אדס (לא קמפיין אמיתי)
```

## טכנולוגיות

React + TypeScript + Vite, Tailwind CSS, Recharts, ו-`read-excel-file` לפענוח קבצי Excel בצד הלקוח.
